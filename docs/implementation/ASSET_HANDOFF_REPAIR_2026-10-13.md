# 同伴工程进入空地图：资产下载与导入交付修复

用户提供的 DEBUG 窗口显示地面、雨和 HUD，但没有树林、手部、器具等 GLB 模型。截图能够说明世界已进入部分运行状态，不能单凭截图断言是 Git LFS、导入缓存、引擎版本还是 GPU 故障。本轮修复下载／导入链路，保留模型、材质、玩法及物理参数。

## 远端检查

- 当时远端默认分支实际为 `codex/four-stage-modeling`，源／模型更新已在该分支；没有把未经核实的分支猜测记为根因。
- `git lfs push --all origin codex/four-stage-modeling` 完成 355／355 对象核查，逻辑总量约 5.1 GB。
- 使用空 LFS 缓存与 HTTPS、禁用凭据助手，独立取得 `naifrog_lod2.glb` 的实际 3,673,172 bytes；SHA256 为 `f7222a4377792bbe75825ea43ae4053878ff7a112c67931f00b319c3b82aa78c`，与本地一致。
- 先前源提交 `e7ca6d0` 的 GitHub Actions 已完成导入、错误拦截自检、13 场景合同与两次档案重启，全部通过。该检查不能代替同伴本机的下载／渲染状态。

这些证据确认远端对象和公开下载样本正常；目前没有同伴的终端日志，尚不能确认他们使用的是网页 ZIP、缺少 Git LFS、没有完成编辑器导入，还是其他本机问题。

## 交付变更

新的 [bootstrap_project.py](../../tools/bootstrap_project.py) 提供只读 `--check`、显式 `--download` 和 `--godot` 导入入口。它先验证 LFS 指针、GLB 结构／声明长度、图片标头、JSON、Git 中的 SHA256 身份，再检查生成缓存和源 MD5。`--godot` 使用实际 Godot 4.7.2 编辑器的 `--headless --editor --import`，不把普通 `--path` 启动当作首次导入。

共享的 [RUNTIME_ASSET_PATHS.json](../../assets/refined/RUNTIME_ASSET_PATHS.json) 列出 36 个必需资源：22 个 GLB、11 张绑定纹理和 3 个运行 JSON。除了这些直接依赖，编辑器还会扫描模型导出的附属 PNG。工具从活动资产根与 Git 跟踪文件推导这些文件，并跳过具有 `.gdignore` 祖先的历史目录；当前实际检查范围为 192 项，其中 189 个二进制，包含 156 项导入附属文件。文件逻辑总量约 2.596 GB，同一 LFS 对象的多个别名会去重。没有默认拉取旧奶龙、报告图片和高精 Blender 源工程。

主入口现增加 [asset_readiness.gd](../../scripts/core/asset_readiness.gd) 的轻量检查。模型仍是指针、文件缺失／截断、图片格式错误、没有导入或缓存丢失时，显示中文资源修复页，阻止生成空 World；选科可以保留，能够返回、修复后重试。检查仅读取短标头和导入／remap 元数据，不重复加载大网格，也不宣称能验证 GPU 或全部模型语义。

导出配置显式包含新运行清单和 `PHYSICS_ENVELOPE.json`，并验证只有 remap／缓存、没有原始 GLB 的真实 PCK。CI 改为按同一交付工具取得活动资产并导入，再运行完整套件，避免为每次测试下载全部历史源模型。

## 实际验证

- Python 工具 11 项夹具通过，覆盖指针、GLB 长度、缺失／过期缓存、只读模式、错误引擎、零退出 ERROR，以及未列在直接清单中的附属 PNG 指针。
- 新原生合同对五种真实交付失败分别调用 Main 入口，World 创建次数为零，菜单／选科可恢复；修复一次性夹具后重试成功。没有把正式模型改成指针来测试。
- 一个没有 `.godot` 的独立 Git 检出先实际识别出 LFS 指针。随后通过工具从已有、已核验的本地 LFS 对象缓存填充文件，并执行真实冷导入；192 项源文件与匹配缓存通过。这个测试不冒充重新从网络下载了全部 2 GB；网络证据独立列在上方。
- 从该检出的真实 Main 入口运行 Metal／Forward+、1920×1080 地图渲染，确认手部／谱灯存在、5 个奶蛙资产、1505 个 MeshInstance3D 与 535 个 MultiMeshInstance3D；实际图中树林、地标、手部和器具可见。这是受控原生渲染，不是同伴显卡或普通键鼠整局验收。
- 当前本地完整套件通过导入、错误拦截自检、14 场景合同及两次档案重启。
- 新独立 macOS 应用导出、release headless 菜单、签名验证及真实 PCK 检查通过；PCK 内 36 项资源前置检查通过，World 与五只追猎者可创建。

完整下载与恢复命令见 [GETTING_STARTED.md](../GETTING_STARTED.md)。如果工具已经报告源文件及缓存全部通过，而同伴仍看不到模型，需要其实际 Godot 版本、渲染器信息和完整运行错误，继续区分 GPU／渲染问题；本次检查没有冒充已访问两位同伴的机器。
