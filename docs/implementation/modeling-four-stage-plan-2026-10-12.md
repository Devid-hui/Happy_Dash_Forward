# Happy Dash Forward：四阶段精细化建模实施方案

本方案依据 20:03 起的原讨论与恢复会话的实际选择编写。视觉方向为统一精细风格化，交付顺序为 1920×1080 UI、全场景静态精修、动态精修、奶龙专项精修。新技能和科研成长同时纳入。当前产出是实施设计，尚未创建新版模型、动画或游戏代码。

用户已确认的完整决策见 [讨论恢复记录](/Users/lpz/Documents/Codex/2026-10-12/codex-threads-01a12ea7-2c11-7112-8b57-2/outputs/modeling-discussion-recovery-2026-10-12.md)。本文件中具体零件、动作拆分和制作组织属于实施方案；精度、时长、能量数值和距离门槛须通过原型核对，不标成用户已经指定的参数。

**1. 先完成 1920×1080 界面。**

主菜单、八项可选技能的选择页、游戏 HUD、手册、暂停、结局、报告强化和研究档案一起迁移。沿用现有界面与暂停管理边界，统一字体、间距和容器布局；保留换行、滚动和真实投影坐标，避免只放大配置字段。

HUD 清楚区分体力、共享电量、谱灯释放模式、乱频噪声、三个装备槽及本局等级。以实际第一人称手部和谱灯的画面占用检查布局，任务和警告不能遮挡路线。持续显示必要状态，短时变化用就近反馈；完整学科说明留在手册和研究档案。

每份报告收集后暂停，选择强化谱灯或本局已装备能力。候选项说明当前等级、下一等级收益和仍存在的代价。报告收集、等待选择与强化确认分别保存，重复事件不能重复强化；失焦和切换面板不能丢失待选机会。第三份报告的出口条件与强化流程共同核对。

本阶段以真实 1080p 窗口确认文字、布局、焦点、鼠标释放、暂停恢复、投影标记和面板内容，不以截图尺寸代替实际窗口状态。

**2. 再完成全场景静态精修。**

| 资产组 | 具体制作内容 | 验收关注点 |
| --- | --- | --- |
| 森林 | 树干与根部的连续形体、主枝和分叉、树冠与叶簇、枯枝、灌木和落叶；用有限变体建立自然差异。 | 近景结构完整，轮廓与树冠空隙自然，远景不因细节切换明显跳变；碰撞与可通行空间可靠。 |
| 地形地表 | 围绕既有路线、地标和边界细化地面形体、湿润泥土、石块、落叶与局部积水外观。 | 路面与障碍轮廓可辨，贴地关系正确，地表变化不意外阻断任务路线。 |
| 输电塔 | 支撑构件、连接结构、线缆与绝缘部件、金属受光和风化细节。 | 结构可信，线缆不漂浮；科研报告位置和交互仍能接近。 |
| 枯树 | 主干、裂口、根部、断枝与风化表面，保持任务地标的独特轮廓。 | 与普通树可区分，正背光及闪电下结构成立。 |
| 废车 | 车身板件、四轮、车窗、接缝、损坏与湿污表面。 | 部件尺寸与接触关系可信，报告不被车身或碰撞体挡住。 |
| 科研报告 | 封面、纸页、书脊和可辨识的研究标记，与三个地标对应。 | 常用观察距离可以发现和辨认，交互信息清楚；模型精修不改变三份报告的循环。 |
| 谱灯 | 便携科研仪器：光学透镜、储能模块、模式控制、保护外壳、连接与握持结构。 | 第一人称近景形体和材质成立，零件有清楚用途，玻璃与外壳能在雨夜光照下区分。 |
| 手部及技能器具 | 与谱灯配套的持握手部；鲁米诺试剂瓶、盐包、泥浆投放容器等按用途制作；感知类使用仪器模块。 | 手指与握柄／器具接触可信，施用、布设和投放有合适的操作部位，不强制六项各做独立装置。 |

材质与光照共同验收。常态暗处能读近处路面、树干和障碍轮廓；谱灯照亮区域能看清模型和材质；闪电短暂揭示远处环境。精细化要能在实际游玩视角被观察，增加面数不能替代形体、连接和受光效果。

森林同时整理模板缓存、重复网格和材质。合并合适的树皮与叶簇部件，批量植被按空间分区；分别检查程序资产与导入资产的近远景表示。具体几何量、纹理规格、分区尺寸和距离由目标机器实测确定。

**3. 在静态资产上完善动态与技能表现。**

| 动作或反馈 | 具体表现要求 | 与玩法的对应 |
| --- | --- | --- |
| 谱灯常态与照明 | 单手持握，步行与奔跑的姿态变化适度；开关和光束方向清楚。 | 照明独立控制并消耗共享电量，画面始终保留路线观察空间。 |
| 集中爆发 | 另一手辅助支撑、集中释放、恢复单手姿态；设备和手部一起反馈。 | 使用现有储能进行爆发，强光后有短暂视线代价；效果是击退用途。 |
| 乱频点射 | 单手姿态下有可区分的短促释放反馈；切换模式有明确动作和状态显示。 | 技能键切换爆发／点射，按次耗电并累积噪声；照明保持独立。 |
| 蓄昼捕光与加速 | 闪电时的储能反馈与主动加速反馈分开；表现短促、可控的错乱。 | 装备后被动捕光，主动使用共享电量加速，维持既定副作用边界。 |
| 原六项技能 | 施用、布设和投放类有相应手部操作；感知类有模块操作、界面及声光反馈。 | 保留各自用途、装备关系与实际代价，反馈须与施放成功、拒绝和冷却一致。 |
| 雨夜与植被 | 雨幕、地面反馈、闪电、环境声音和适当的植被动态共同形成层次。 | 从不同视角确认可见性，闪电与技能反馈不掩盖路线和重要提示。 |
| 基础角色动态 | 将现有追逐、预警、冲刺等状态接到对应表现，为奶龙专项精修准备状态衔接。 | 动作跟随实际游戏状态，视觉动作不额外驱动物理根的位置。 |

动画不能丢失资源反馈或吞掉正常输入；暂停时冻结，恢复后连续，重开和切场景时正确收尾。蓄昼与乱频的副作用为明显但可控的视听干扰和短促步态偏移，保留基本操作；降低画面干扰时仍保留资源和战术代价，暂停、手册和菜单始终可操作。

**4. 最后专项精修奶龙。**

采用常见奶龙的圆润大头、大肚子和黄胖整体形象，细化脸部、眼睛、嘴部、四肢、尾部及表面。危险感由表情、姿态、追逐、预警和冲刺构成，沿用已经选择的造型边界。

动作重点检查站立与呼吸、行走、追逐、预警蓄势、冲刺和恢复的衔接；脚部接地、身体重量和腹部运动要可信，不能只平移整只模型。精修与当前玩法状态对应，不借美术工作改变已定的敌人数量、装备结构或逃生条件。

五只奶龙可以共享网格、材质和纹理，但骨骼、动画状态及局部反馈分别独立。动画要有覆盖各姿态的保守边界，同时供渲染与视野保护使用；相机边缘仍可见时不能被传走。保持物理根、视觉容器及现有玩法信号的边界。

**科研成长与模型表现一起完成。**

谱灯不占槽；原六技能加蓄昼、乱频供最多三个槽选择。照明、爆发、点射、加速共享电量并保留慢速恢复。各能力采用基础、进阶、精修三级，每次强化提供清楚收益；三份报告各提供一次自主强化，允许专精或分散投入，不要求全部能力升满。集齐三份报告后开启出口。

研究界面、器具状态和技能反馈显示实际本局等级。长期档案独立记录知识、报告和融合发现，不提供永久数值优势；本局等级重置，本局发现提示仍按本局实际触发。科学说明分清真实原理与游戏放大。能量、恢复、充能、技能时长、噪声和升级数值属于原型参数，实施时须记录具体初值、对应测试和调整依据；本建模方案不把未测试数值标为已平衡。

**验收与交付对应每个阶段。**

保留阶段差异、正式游戏使用的资产来源、固定视角模型预览，以及常态暗场、谱灯照明和闪电下的实际画面。静态预览用于核对造型与材质，游戏内操作用于核对动作、状态与可读性，两类证据分别保留。

功能回归覆盖现有输入与暂停、报告和强化幂等、能力等级及资源、档案重启读取、动作实例独立、视野边缘保护、死亡补位与场景重建。真实操作检查第一人称手部、器具施放、雨幕、追逐和整局路线，结果按实际观察记录。

性能在 M4 Pro、实际 1920×1080 窗口、雨夜和五只追猎者条件下测量，包含普通探索、闪电、技能集中施放、追逐及多次重开。报告帧时间分位数、绘制成本和内存变化，并以约 16.7 ms 的 60 FPS 帧预算收敛资产成本；旧 640×360 测量只作历史基线。

实施前保留已核对的 `d4ac3bc` 基线，在本地独立分支记录阶段修改。当前已经完成需求恢复、选择留存和实施设计；新版模型、动画、功能实现及上述新版测试仍未执行。原 `grill-me`／现 `grilling` 的访谈边界继续有效，明确要求执行后直接沿用这份方案推进，无需重新确认已定选择。
