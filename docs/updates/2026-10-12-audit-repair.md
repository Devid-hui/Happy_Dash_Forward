## 性能测量

在同一台 Apple M4 Pro（12 个逻辑 CPU）上，Godot 4.7.2、Metal / Forward+、640×360 窗口与画布，关闭垂直同步和帧率上限，固定种子 721 与镜头路线。修前、修后各三组，逐组预热 5 秒再采样 60 秒；首组之后连续重建世界十次。有效采样期间没有并行引擎测试、导出或 UI 测试。

修后性能样本针对 F01–F13 完成后的代码版本；随后 F14 只修正提示文案及槽位选择，没有重跑六组性能采样。以下是各组三个分位数的中位数：

| 指标 | 修前 | 修后 | 变化 |
| --- | ---: | ---: | ---: |
| 墙钟帧间隔 p95 | 13.35 ms | 13.31 ms | −0.3% |
| 墙钟帧间隔 p99 | 17.68 ms | 17.46 ms | −1.2% |
| 每秒最大处理时间监测值 p95 | 24.01 ms | 24.09 ms | +0.3% |
| 绘制调用 p95 | 4434.20 | 4438.95 | +0.1% |

`TIME_PROCESS` 是 Godot 每秒记录的前一窗口最大处理时间，其分位数不等同逐帧 CPU/GPU 耗时；未独立测量 GPU 时间。性能脚本设置玩家位置并抑制测试场景的失焦/结局暂停，保留五只敌人、森林、雨效、闪电和音频；不代表真实行走、技能集中施放或自然通关。

十次重建后节点稳定在修前 6042、修后 6050，增加的八个节点来自四面边界与碰撞形状；孤立节点为零。第 1 到第 10 次重建，静态内存两版均增加约 0.02 MiB，RSS 修前增加 2.98 MiB、修后增加 2.91 MiB。有限短测不能区分缓存保留与长期持续泄漏，也不能据此承诺其他硬件、分辨率或工作负载的帧率。
